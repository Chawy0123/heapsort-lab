排序原理

Heap Sort 分成「建立最大堆積」與「重複取出最大值」兩個階段。

為什麼最大值永遠在第 0 格？

Max-Heap 是一棵完全二元樹，而且每一個父節點都大於或等於自己的子節點。因此根節點一定是整個堆積區的最大值；使用陣列儲存時，根就是索引 0。

父節點i

左子節點2i + 1

右子節點2i + 2

兩個階段

  1. 建立 Max-Heap 從 floor(n / 2) - 1 開始往前做 siftDown，讓最大值移到堆頂。
  2. 連續取出最大值 把索引 0 與堆積區最後一格交換，縮小 heapSize，再從根節點向下調整。
JavaScript 核心程式 heapSort.js 
function heapSort(array) {
  const n = array.length;

  // 1. 由下往上建立最大堆積
  for (let i = Math.floor(n / 2) - 1; i >= 0; i--) {
    siftDown(array, i, n);
  }

  // 2. 把每輪最大值放到已排序區
  for (let end = n - 1; end > 0; end--) {
    [array[0], array[end]] = [array[end], array[0]];
    siftDown(array, 0, end);
  }

  return array;
}

複雜度比較

Heap Sort 的優勢會在資料量增加時愈來愈明顯。

Heap Sort 與 Bubble Sort 比較
項目Heap SortBubble Sort
最佳時間O(n log n)O(n)需有提前終止最佳化
平均時間O(n log n)O(n²)
最差時間O(n log n)O(n²)
額外空間O(1)O(1)
穩定性不穩定穩定

Bubble Sort 必須反覆比較相鄰元素，平均與最差情況約做 n² 次工作；Heap Sort 每輪下沉最多走樹高 log n，而且只做 n 輪，所以不論原始資料順序，時間複雜度都維持 O(n log n)。

學習心得

從看懂 Max-Heap，到真正把每一次比較與交換做成可以操作的網站。

一開始學 Heap Sort 時，我只記得「先建立最大堆積，再一直取出最大值」這句話，但沒有真正理解為什麼它能完成排序。實作互動網站後，我才看清楚 Max-Heap 的價值：因為每個父節點都不小於子節點，所以目前最大值永遠在索引 0。每一輪不必重新掃描整個陣列找最大值，只要讀取堆頂就能立刻找到它。

我也更清楚建堆與正式排序是兩個不同階段。建堆從最後一個有孩子的節點 floor(n / 2) - 1 開始，逐步向前做 siftDown；完成後的陣列雖然還不是遞增順序，卻已經符合 Max-Heap。正式排序才會把根節點和堆積區最後一格交換，讓最大值進入最右側的已排序區。

實作過程中最容易出錯的是 heapSize。每取出一個最大值，heapSize 就必須縮小一格，而且後續 siftDown 絕對不能碰到右側已排序區。只要邊界多算或少算一格，剛排好的最大值就可能被換回去。把堆積區與已排序區畫成不同顏色後，我比較容易檢查這個問題，也真正理解「原地排序」如何在同一個陣列中完成。

二元樹與陣列的對應也從抽象公式變得具體。父節點在 i 時，左孩子是 2i + 1，右孩子是 2i + 2。網站同時顯示樹和陣列，讓我看到樹上的一次交換，其實只是陣列中兩個索引的值互換；資料並沒有另外複製成一棵樹。這讓我對完全二元樹的儲存方式更有把握。

最後，和 Bubble Sort 比較後，我對時間複雜度的差異有更直觀的感受。資料量小時，兩者看起來都很快；但 n 增加後，O(n log n) 與 O(n²) 的成長差距會迅速拉開。我也用已排序、反向、重複值、負數、零與只有兩個元素等特殊資料測試，確認每一輪取出的確實是當時堆積區的最大值，而不是只對單一範例剛好成功。

這次作品不只讓我背會 Heap Sort 的步驟，也讓我練習把演算法拆成可驗證的狀態：建堆、比較、交換、縮小堆積區、完成。之後遇到其他資料結構或排序問題時，我會先釐清資料的表示方式、每一步必須維持的條件，以及哪些特殊輸入最容易讓程式出錯。
